# VHS-55 — Stakes tier at preflight: the brief declares a Tier and spec-cycle / ship-spec scale ceremony to it
**Status:** Todo · **Priority:** high · **Assignee:** unassigned
**Created:** 2026-10-11 · **Plane:** VHS-55 (b1ebf253-705f-4b16-b780-a5ed44c25a41, Todo)
**Origin:** Filed 2026-10-11 from the skill-pack distillation (vigil-harbor-wiki `overview/2026-10-11-skill-pack-distillation.md`, § 3 item 1), which audited 350 session transcripts and found that every ticket pays the same lifecycle cost regardless of stakes. The idea is Rob Shocks' ceremony ladder (tweak / small / big / irreversible) and Osmani's `/ship` skip rule. The interview ran 2026-10-11 and settled every candidate decision at brief altitude; three Codex (gpt-5.6-sol) adversarial review rounds returned RED (9, 8, then 2 findings, each round on different ground); all are folded below except the size-heuristic one, which is Risk 2. The review stopped at the three-cycle bound; no fourth pass was run. Round 2 reversed one interview answer: Q15's headless default is now "stop", because spec-brief has other mandatory waits that make a headless run impossible anyway (D11).

## Problem

Every ticket gets the same lifecycle: three or four reviewer lenses for up to four rounds, then ship-spec with the full gate. A 3-lens 4-round cycle costs about 1.5M tokens (session 65c6bd2b 2026-10-08 measured 90 to 165K per reviewer per round). About 11 red-after-4 halts since 2026-09-06, most of them specs for the skills repo. The operator decides tier by hand every time: "if the fix is genuinely trivial, then we can write it now" (9f6aae9d 09-08); "ship the tiny ones with no spec, as CLT-130 and CLT-132 did?" (17ef0037 09-26); "shouldn't go through the spec lifecycle" (4ddc890e 09-08). Factory mode (6b4468bf 10-03: 12 Opus-drafted briefs, 13 concurrent cycles) exists because the per-ticket path is too heavy, and intent is lost in relay.

## Why it matters

Ceremony should match the stakes. Without a declared tier, the lifecycle's cost is fixed at its maximum, so operators route around it by hand (chore PRs, factory mode, "write it now"), and the decision of how much review a change deserves is made in conversation and recorded nowhere. Every other ticket in the 2026-10 sprint gets cheaper once this lands.

## Decisions carried forward

1. **Four tiers** (Q1) — tweak / small / big / irreversible. `irreversible` is `big` plus reviewer context plus an unskippable ship-spec review gate. Scale stays its own declaration; a tier never sets `scale_lens`, because the scalability lens needs a `**Target:**` line (F3).
2. **Carrier: brief section → spec Decision → verdict marker field** (Q2) — spec-brief writes `## Tier`; spec-cycle records it as a carried-forward Decision in Phase 1 (D12 line shape) and writes `tier:` into `verdict.md` at every marker write point, including attest mode, which reads the recorded Tier Decision from the spec (absent → `big`; malformed → halt) since it runs none of Phase 0 steps 2 to 8 (F10). The brief is the initial source; once the spec exists, its recorded Tier Decision is authoritative (the re-run pin, F2). ship-spec never reads the brief: it reads the spec's recorded Tier Decision every time, as the authoritative value, and reads the marker's `tier:` line as a consistency check; a marker `tier:` that is malformed or disagrees with the spec puts the marker in the `changed` state (confirm, F7) while the spec's value still governs; a marker with no `tier:` line (pre-VHS-55) is not a disagreement. Absent in the spec means `big`. An `irreversible` tier fails closed: whatever the marker state and whatever the operator confirmed through, ship-spec never proceeds past a skipped review gate (D8). Follows the path `## Scale` already walks (F6, F7).
3. **The operator sets the tier** (Q3) — spec-brief recommends a default computed from the ticket text and grounding facts (files the ticket names, wiki filemap rows, surfaces, reversibility) and asks; the tier is never auto-set, with no exception (D11).
4. **Tweak floor heuristic** (Q4) — the recommendation says `tweak` only when the change is at most 2 files, under 50 lines, and touches nothing in auth, payments, data, or config; a change in any of those four areas is never recommended `tweak`, whatever its size. The numbers are an estimate from the ticket and grounding (Risk 2).
5. **A tweak writes nothing** (Q5) — spec-brief prints a NEXT block and stops: "no lifecycle — ship as a chore PR citing the ticket; the ticket's state and closing comment are yours to set, since no lifecycle stage will touch it" (spec-brief never transitions a ticket, F14, and ship-spec's Phase 6 Plane update is the only stage that does, F15). When the Phase 0 collision gate found an existing brief, spec, or reviews tree and the operator chose to proceed, a later `tweak` choice does not print the NEXT block: it stops with a block listing those paths and stating that they stay actionable by ship-spec and spec-close until the operator removes or archives them and re-runs spec-brief clean; spec-brief deletes nothing but its own temp file (F14). `tweak` is never a value that reaches a brief, a spec, or a marker.
6. **Tier asked after the seed gate and before the interview** (Q6) — the seed gate (F9) runs first in every mode, so an empty seed still halts before any tier question; the tier gate then runs, including under `--no-grill`; `tweak` exits at once, any other tier proceeds to the interview or, under `--no-grill`, to Confirm. The Confirm step (Phase 3) can change the tier; a change to `tweak` there prints the same NEXT block and exits before Phase 4 with no brief written.
7. **Small tier shape** (Q7) — all three standing lenses; `round_cap = 2` instead of 4; ship-spec skips the review gate and keeps the test gate. `round_cap` is one parameter and every round range is stated against it algebraically, not by substituting the literal 4: ordinary revision runs while `round < round_cap`; the recount's revert-the-original-fold path is available for `2 ≤ round < round_cap` (today "round 2 or 3", F16) and unavailable in the final round; the final round `round == round_cap` gets the FROZEN/REWRITE targeted rewrite; the closed-issues manifest and the FROZEN test cover rounds `1 .. round_cap − 1` (today "rounds 1–3"); 2f halts after round `round_cap` with the red marker's `round:` field, the halt text, the report paths and 2f-i all reading the parameter. `round_cap` is the review-loop cap only; the grilling interview that 2f-i option 4 runs keeps its own independent round cap of 3 (F17). Rationale: VHS-27's evidence that genuine misses dry up after round 2 and later rounds review the fixes.
8. **Irreversible makes every review-gate skip a halt** (Q8, widened) — the three Phase 3b skip cases today are no command declared, command not available, and command failed or returned nothing readable (F11). For `irreversible`, each becomes a halt before the commit that names the case, keeps the worktree, and waits: option 1 re-resolves the review command (Phase 0 step 4b) and runs Phase 3b again in the same run; option 2 stops with the worktree kept and a warning that `git worktree remove --force` discards the uncommitted implementation. A host that cannot wait takes option 2. The return is classified by three ordered tests: readable findings anywhere continue to steps 4 to 8 whatever the exit code; otherwise the reviewer's own affirmative clean statement is success; otherwise `failed`, which includes empty output, so a broken or silent reviewer can never pass the gate unnoticed and the halt names the remedy. In subagent mode the subagent reports `ran: yes | no` and passes the reviewer's output through verbatim. The once-per-run rule counts passes that ran; the halt's option 1 is the only route to another pass and is available after every halt. The halt names the file the command came from and says repairs go in the primary checkout. Nothing is committed until the gate has run. (Folded after the round-3 green from Deferred rows D-1 and D-2, under the operator's standing ruling that in-scope P1s fold.)
9. **No `## Tier` section means `big`** (Q12) — today's behaviour exactly, with no warning, since the lens and round arithmetic are unchanged. Only true absence defaults; see D12 for malformed values.
10. **Every reviewer prompt carries `tier: <value>`** (Q13) — all tiers, all four lenses, added to each agent's enumerated input list (F13). It is context for the lens's judgement of blast radius and reversibility; the shared P0/P1 definitions are tier-independent.
11. **A host that cannot wait stops at the tier gate** (Q15, reversed after Codex round 2) — print `tier needs an operator — stopping` and stop, the same rule ship-spec and attest mode use (F12, F10). The interview's Q15 answer was "default to `big`" so headless lanes could run briefs; that premise was wrong: the interview waits every round and `--no-grill` still reaches the mandatory Confirm wait (F9), so no headless path through spec-brief exists and a default would only move the stop one gate later. Stopping keeps D3 exception-free.
12. **Grammar, in the brief and in the spec** (from Codex findings 7 and 4) — in the brief: a whole-word `## Tier` heading, then a `**Level:** small | big | irreversible` line, mirroring `## Scale` (F2); room for sibling lines is reserved for VHS-54. In the spec: the recorded Tier Decision is a `**Tier:** small | big | irreversible` line, found as the first such line anywhere in the spec rather than under a named heading, because spec-cycle requires Decision subsections without pinning their heading form and existing specs vary (F18); it is the shape every reader uses: spec-cycle's re-run pin, attest mode, and ship-spec (D2). In both files the first matching line wins and duplicates warn, as Scale does. A level that is missing from a present section, unknown, or `tweak` halts the reader rather than downgrading, so an intended `irreversible` is never silently read as `big`.

## Done when

- spec-brief: a non-tweak brief carries `## Tier` with a `**Level:**` line; a `tweak`, chosen at the tier gate or at Confirm, writes nothing and prints the NEXT block, or stops naming the stale artifacts when the collision gate found any; the seed gate runs before the tier gate in every mode; a host that cannot wait stops at the tier gate.
- spec-cycle: records the Tier Decision as a `**Tier:**` line, writes `tier:` on every marker write including attest mode, runs `small` with `round_cap = 2` (revision in round 1, rewrite in round 2, no fold reversion in round 2), and passes `tier` to every reviewer prompt.
- ship-spec: reads the spec's `**Tier:**` line as the tier and treats a malformed or disagreeing marker `tier:` as the `changed` state; `small` skips the review gate; `irreversible` halts on a missing, unavailable, or failed review command in every marker state, keeps the worktree, and offers to re-run the gate in the same run; a review that affirmatively states no findings, or a non-zero exit with readable findings, is success, and empty output is `failed`.
- A brief with no `## Tier` section, and a spec with no `**Tier:**` line, behave exactly as today; a malformed `## Tier` or `**Tier:**` halts the reader.
- `docs/spec-workflow-reference.md` and `AGENTS.md` describe the ladder.
- Lint and tests pass.

## Out of scope

- `--tier` override flags on `/spec-cycle` or `/ship-spec` (Q9): the brief is the only initial source of the tier and the spec's recorded Decision the only source after authorship; to change it, edit the brief and, when a spec exists, the recorded Decision, which the re-run pin already governs. No flag and no conversation can set it.
- Executor per stage (Q10): VHS-54 owns which executor runs each stage; this brief only requires that the `## Tier` section shape leave room for sibling lines, the way `## Scale` has `Factor`, `Target`, `Dimensions`.
- spec-close (Q11): a tweak writes no artifact, so there is nothing to close; every other tier closes as today.
- Changing which lenses run per tier: the lens set is fixed; only `round_cap` and the ship-spec gate vary (Q7, Q1).
- Changing the shared P0/P1 severity definitions by tier (D10).
- The brief doubt pass (VHS-56) and delta-scoped passes (VHS-27): they may later attach to tiers, but nothing here depends on them.

## Risks / decisions

1. `/spec-tickets` also reads the verdict marker; the marker contract says a reader takes the first line for each key and ignores anything else (F7), so an added `tier:` line should be inert there — the spec author verifies this against `skills/spec-tickets/SKILL.md` before relying on it; spec author pins this.
2. The tweak heuristic (D4) has no measurable diff before implementation and "data" and "config" are undefined surfaces. The spec author pins: the estimate's source (the ticket text and the Phase 1 grounding facts, since Scope rows do not exist before the interview), the one-line basis the recommendation prints, a short surface taxonomy for auth / payments / data / config with a per-project extension point in the project's instructions file, the fallback when the estimate is unknown (never recommend `tweak`), and two or three worked examples for the recommendation's basis line; spec author pins this.
