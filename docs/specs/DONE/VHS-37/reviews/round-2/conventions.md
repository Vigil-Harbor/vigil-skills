### F-1: Round 2's new row-mutation rules are absent from the `### Minor additions` roll-up the spec built for exactly this purpose
**Severity:** P2
**Pre-ship recommended:** yes
**Where:** spec.md:76-77 (`### Minor additions`), against spec.md:126 (R2(c)), :94 (Design 1 step 4), :88 (Design 1 step 2)
**Convention violated:** `docs/spec-workflow-reference.md:77` / `AGENTS.md` § Parallel review agents — the conventions lens classifies every decision as brief-authorized, ticket-authorized, spec-addition-with-rationale, or silent addition; and this spec's own declared device at :76, *"Recorded so the drift-check can see them"*. Round-1 conventions F-4 established the precedent for precisely this class and was applied.
**Evidence:** The roll-up at :77 records twelve items — including the re-anchor markers added last round, the `(none)` render, the `routing violation:` title prefix, and the round-4 title suffixes. It does not record this round's additions, two of which are more load-bearing than anything already listed:

- **R2(c) discharge and the optional `Discharged:` field** (:126). This is a third class of skill edit to a persisted row — the first that folds a finding *out* of the section — and it is the only escape from the in-scope-P0 gate deadlock. It also drives a qualification in the reviewers' ceiling test (:181) and a special case in Design 5's render (:166). The brief authorizes nothing about it: brief:21's Scope row lists the row's eight items and stops; brief Decision 2 says an in-scope P0 "must be folded", not that a row may later be discharged.
- **Design 1 step 4's same-root row repair** (:94) — "first check `## Deferred — follow-up required` for a row with the same root … repair that row under R2(a) instead of appending". A second entrance into R2(a) that the brief does not describe.

Three smaller ones are also unrecorded: the no-Scope-table / no-Out-of-scope-list default to in-scope (:88), the section→file-region subject-mapping rule the author and the conventions lens both run (:88), and "a blank line is stored as a bare `>`" (:115). All are (c)-class — rationale exists, but it lives in `round-1/{correctness,edge-cases}.md`, and the Phase 3 drift-check reads the spec, not the review directory.
**Suggested fix:** Append to the roll-up at :77, in the existing comma-run style: *"a row the reviewers filed a ceiling-class routing violation against, or whose `Scope` repair makes it an in-scope P0 row, is discharged by folding at every listed site and appending a `Discharged:` field — the only skill edit that resolves a row rather than relocating it, and the reason the reviewers' ceiling test is conditional; a defer whose root already has a row repairs that row under R2(a) instead of appending a second; a brief with no Scope table or no Out-of-scope list classifies in-scope by default; scope is compared by mapping the spec section to the file region it governs; a blank line inside a stored `Suggested fix` is a bare `>`."*

### F-2: The `AGENTS.md` / reference-doc reconciliation imports the skill's internal step code `2e` into two tracked docs that use no step codes at all
**Severity:** P2
**Pre-ship recommended:** yes
**Where:** spec.md:21 (Scope row), spec.md:200 (checklist row 10)
**Convention violated:** The written register of `AGENTS.md` and `docs/spec-workflow-reference.md` — both describe the loop in prose and renumbered steps, never by the skill's internal `2a`–`2g` labels — plus the operator's recorded preference for glossing internal codes on first use (memory: *"Grill rounds: plain language — gloss internal codes (2f-i, empty-frontier) on first use"*).
**Evidence:** `grep -nE '\b2[a-g]\b' AGENTS.md docs/spec-workflow-reference.md` → **zero hits in both files**. The reference doc deliberately re-expresses the loop as numbered steps 1–8 (`:81-86`) rather than reusing `2b`/`2d`/`2e`; `AGENTS.md`'s § Conventions bullet at `:101` is a one-line severity definition shared by *all* reviewers, including the direct-dispatch path the scalability agent documents at `agents/spec-reviewer-scalability.md:44` ("a host that dispatches the agent directly, outside spec-cycle's gate"). The spec pins the literal — *"unless routed to `## Deferred — follow-up required` under 2e's ceiling"* — into both, and row 10 greps `unless routed to` → 1 in each, so the wording ships as written. A reader of `AGENTS.md` has no way to resolve "2e"; a reviewer dispatched outside spec-cycle has no 2e at all.

Secondary, same clause: "P0/P1 block shipping unless routed to …" is a slightly inaccurate compression of the mechanism the spec actually builds. Nothing about an emitted P0/P1 stops blocking — Decision 1 (:31) is explicit that the gate formula and `total_p0p1` are untouched. What changes is that a reviewer no longer *emits* a finding a well-formed row already carries.
**Suggested fix:** Keep the reconciliation (round-1 F-3 was right that it is owed) but drop the internal code and state the mechanism: *"P0/P1 block shipping; P2+ do not — except that a finding the author routed to the spec's `## Deferred — follow-up required` section, under the scope ceiling, is not re-filed by the reviewers and so never enters the gate."* Adjust row 10's grep literal to a phrase that survives (e.g. `grep -cF 'Deferred — follow-up required' AGENTS.md` → 1), and keep it on a single line per the Test-plan preamble at :189.

### F-4: Design 5's `Discharged:` render replaces the ticket id, contradicting the Done-when mapping's "renders the field's value verbatim"
**Severity:** P3
**Where:** spec.md:166 (Design 5 extraction rule) vs spec.md:215 (Done-when bullet 2)
**Convention violated:** Internal consistency between the Done-when map and the Design section it cites — the spec's own device of mapping each Done-when 1:1 to a mechanism (:212).
**Evidence:** Done-when bullet 2 reads *"Deferred entries that become tickets carry the ticket id. — Design 2's `Follow-up:` field with D12's backfill rule and rule R4's re-run preservation; **Design 5 renders the field's value verbatim**."* Design 5 now says *"`Follow-up:` is printed verbatim, **except that a row carrying `Discharged:` prints that field's value in the Follow-up column**"*. So for a row the operator already filed as `VHS-99` and that a later round discharges, the render prints `folded round 3 — § a; § b` and the ticket id disappears from what Design 6 (:173) calls *"the only reminder"* — leaving an open ticket the operator can no longer see from the console. The criterion itself still holds (the row on disk carries the id), so this is a wording/rendering mismatch, not a broken Done-when.

This is adjacent to, but not a re-file of, the already-adjudicated `edge-cases/R2/F-10` (:242, "the skill does not judge whether a row is resolved"): a `Discharged:` row is the one case where the skill *did* the fold and does know, which is why Design 5 special-cases it at all.
**Suggested fix:** Make `Discharged:` an added token rather than a replacement — *"`Follow-up:` is printed verbatim; a row carrying `Discharged:` additionally prints ` [discharged: <value>]` after it"* — and leave :215 unedited. If the replacement is intended, amend :215 to *"Design 5 renders the field's value verbatim, except on a discharged row"* so the mapping is not falsified.
